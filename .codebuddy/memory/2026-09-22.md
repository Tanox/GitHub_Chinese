## 修复：词典采集清洗链路路径 bug（v1.9.24 → v1.9.25）

- 根因：`src/lib/collector-logic.ts` 的 `runDictionaryProcessor()` 把原文写到 `os.tmpdir()/github-i18n-raw-terms.txt`，
  却仅以 `path.basename(RAW_TERMS_FILE)` 把文件名传给 `collect-dict.cjs`；子进程用 `fs.readFileSync(argv[2])`
  按 `process.cwd()`（项目根）解析 → ENOENT，导致「智能清洗/开始分析/批量抓取」的清洗步骤全部失败（SSE 返回 error）。
- 修复：传完整路径 `RAW_TERMS_FILE` 给子进程。
- 顺带：`/api/collect`、`/api/batch-collect` 的 `await req.json()` 包 try/catch，非法 JSON 返回 400（原 500）；
  `catch (err: any)` 改 `catch (err: unknown)` 收窄。
- 版本同步：src/version.js、package.json、README 徽章、CHANGELOG 新增 1.9.25 小节；被改文件头注释升 1.9.25。
- 校验：`npx eslint` 与 `tsc --noEmit` 均 0 错误。
- 注：docs/openspec 正文版本行（"版本：**v1.9.24**"）未批量更新，按用户规则仅同步全局单一来源展示位。

## 优先处理 P1-2：移除未引用的 i18n 框架（仍属 v1.9.26）

- 用户指示「优先 P1-2」，采纳先前给出的推荐选项 **B（移除）**。
- 决策前的取证：用 import 说明符精确检索（`from '.*i18n'` / `initI18n` / `i18nManager` / `builtinTranslations`），
  确认全部匹配都落在 `src/i18n*` 自身内部，**零外部引用**（此前 27 个文件的粗匹配是 `GitHub_i18n`

  4. 框架还带 locale 持久化与无人订阅的 observer，属纯死重。
- 执行：删除 `src/i18n.js` + `src/i18n/{constants,formatters,loader,lookup,manager,observers,storage,translations}.js`
  （9 文件 / 641 行）。
- 验证：`node build.cjs` 输出**不再有「未被入口引用」段落**（孤立模块 9 → 0）；模块数仍 92、
  产物仍 193.70 KB（i18n 本就未参与打包）；`npm run test` 全绿；`npm run build:web` 路由不变。
