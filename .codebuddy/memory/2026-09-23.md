## 独立代码审查（v1.9.42，用户「审查项目」）

对当前真实代码（非记忆）派两个 code-explorer 子代理并行复查，结论：工程化健康（strict 零 any、零 TODO 债、CI 完整、CSP 完备、SSRF 静态层到位），但发现 T1–T11 之外的**新短板**：

### 安全（P0/P1/P2）
- **P0 SSRF 重定向绕过**：`collector-core.js:126` `page.goto` 默认跟随重定向，已通过 `guardUrl` 的公网 URL 可 302 跳 `169.254.169.254` 元数据 → 防护失效。需 `setRequestInterception` 对重定向目标二次校验。
- **P0 无鉴权 + 无限流/URL 数上限**：两 API 无 auth；每请求 `puppeteer.launch` 无沙箱 Chrome（`collector-core.js:113`），`batch-collect` 串行 goto 30s/页、无 URL 数/请求体大小上限 → 公网暴露即 DoS/SSRF 入口。文档须显著标注「禁止公网暴露」。
- **P1 非常规 IP 字面量绕过**：十进制 `2130706433`/八进制/十六进制 IP 不匹配 `PRIVATE_IPV4_PATTERN`（`url-guard.js:8-9` 自知限制），Chromium 解析为 127.0.0.1。需解析归一化。
- **P1 固定临时文件竞态 + 未清理**：`RAW_TERMS_FILE`（`dictionary-processor.js:23`）非随机名、`collectFromUrls`/`processRawData` 共用 → 并发覆盖；无 `unlink`。
- **P2 子进程错误泄露绝对路径**：`collect-dict.cjs:119` 经 SSE 回传客户端（`dictionary-processor.js:72-73`）。
